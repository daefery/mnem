Memory for coding agents · comparison, September 2026

The agents already write everything down. mnem just reads it.

Claude Code, Codex and pi each append every prompt, answer, command and edit to a transcript on disk. mnem indexes those files directly, so capture never waits on an LLM, a worker, or a queue, and one memory is shared by every agent you run.

The case

Why mnem, and where it is behind

Where mnem leads

Capture cannot silently failEvery other tool depends on a hook or an API call succeeding at the moment work happens. mnem reads the transcript the agent already wrote and commits the read position with the events, so a missed hook or crash only delays capture. mnem doctor reports lag and lost bytes instead of staying quiet.
One memory, live across agentsClaude Code, Codex and pi read and write the same store. On every prompt, a session is told what other sessions in the same project did since it last looked. agentmemory also shares one store across agents; no tool we checked documents per-prompt “meanwhile” updates.
Nothing to babysitOne 10.8 MB binary and a 19.5 MB background service. No Node, Bun, Python, Docker, vector database or cloud account. The closest light alternative, claude-mem-lite, supports Claude Code only.
Your models, no extra subscriptionSummaries go through any OpenAI-compatible endpoint (here CLIProxyAPI) with an ordered model chain. A model that hits quota cools down and the next one takes over; tested live when gemini-3.5-flash-lite returned HTTP 503.
Moving from claude-mem loses nothingImport kept all 58,797 observations with their original ids and all 4,536 summaries, then backfill recovered sessions claude-mem never captured.

Where mnem is behind

No semantic search yetFull-text only. claude-mem, Mem0, Basic Memory, Hindsight and Graphiti all combine keywords with vectors. Planned once a recall test set shows where full-text misses.
No knowledge graph or fact validityGraphiti and Hindsight track entities and when a fact stopped being true. mnem stores observations with timestamps only.
Three agents, not nineagentmemory supports 9 agents and claude-mem 8+ hosts. mnem covers Claude Code, Codex and pi, the three used here.
Single machine, single userNo sync, no team sharing, no cloud option.
Brand new and unproven outside this machinePrivate repository, no licence chosen, one user, no public benchmark. Mem0 publishes a LongMemEval score of 94.4 for its managed platform.
Roadmap · reviewed by a three-model council

Essential now: all seven shipped on 28 September

Each item passed two council code-review rounds before shipping; 60 tests. Prompt recall measures hit@5 87% and MRR 0.68 on 38 known-item questions from real history (p95 about 110 ms). Ordered by value to a daily user divided by effort. GPT-6 Astra, Gemini Pro Agent and Claude Fable 5.1 reviewed and reordered this list; where they disagreed, the reasoning is in the item.

Backups with a tested restore

Done · bf65933

mnem.db is now the only copy of the imported claude-mem history. The council ranked this first unanimously; a backup nobody has restored does not count.watch takes a nightly VACUUM INTO snapshot, keeps 7, records row counts and integrity; mnem restore --verify restores into a scratch copy and runs sample searches. A manual snapshot was taken today (372 MB, integrity ok).

Evidence links for every memory

Done · 058f5e7

Each distilled memory records the transcript events it came from, so an agent can check a claim against what actually happened. Cheap now with 110 distilled memories, costly to retrofit later.memory_evidence(memory_id, event_id, event_hash); digests carry E-ids and distill validates the citations; get_observations prints the evidence; imported memories are marked as having no evidence rather than guessed.

Working-tree snapshot at the end of each turn

Done · 30b656d

Answers the first question of every session: what was I in the middle of? Uncommitted files, unpushed commits and the branch, captured from git.Stop hook runs git status --porcelain -b, rev-list @{u}.., diff --stat; stored as a git_state event; session-start context opens with a “Working tree” section.

Recall based on what you just asked

Done · 1946bea

Today the session-start context is ordered by recency. This adds the memories that match the words and file paths in each prompt, within a small budget and without repeats.One retrieval function shared by hooks, MCP and pi; FTS on prompt terms + paths, top 5, at most 600 characters; recall_seen(session, memory) prevents repeats.

Forget, exclude, remember

Done · 805bbe8

Delete a memory or a whole project and have it stay deleted, then pin facts that every agent should always see.Tombstones checked by backfill, import and distill so nothing comes back; excluded project patterns; remember(text, scope) as an MCP tool and CLI; a “Pinned” context section.

Health alerts you cannot miss

Done · 1bed442

The original problem was silent failure. If capture lags by more than 5 minutes, every model is cooling down, or the last backup is stale, the next session says so.Checks shared by doctor, the context footer and the viewer health pill.

Export and a recall test set

Done · c751806

An open memory tool must let data leave. A small labelled test set turns “search feels better” into a number before adding embeddings.mnem export to JSONL (memories, events, sessions); 30–50 real questions with expected ids; report hit rate and hook p95 in CI.

Nice to have

Semantic searchLocal embeddings stored next to the full-text index, added when the test set shows misses.
File-aware recallFirst as an MCP tool, recall(path); automatic injection on file reads only if it proves useful. The council moved this down: claude-mem’s version added tokens to every read.
Staleness and decayFlag a memory about a file that changed after the memory was written; rank by how often memories are actually fetched.
RetentionPrune raw events after a set age. The database is 362 MB, well within what SQLite handles.

Verdict

Memory you can git blame

mnem is the best fit for this setup today: three agents on one machine, models through CLIProxyAPI, and zero tolerance for silently lost sessions. It is not yet the best at search. Mem0, Hindsight and Graphiti retrieve more cleverly, and agentmemory covers more agents.

The position worth owning is evidence. Capture that cannot lose data, plus a link from every memory to the transcript event behind it, plus the live “meanwhile” updates, makes mnem the one tool whose memories an agent can verify instead of trust. Every competitor summarises first and keeps no source; they cannot add this without storing full transcripts.

Status: the seven essentials shipped on 28 September. Next: semantic search where the recall test shows keyword matching falls short, and a second test set built from real prompts.
