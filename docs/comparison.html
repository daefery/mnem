Memory for coding agents · comparison, September 2026

The agents already write everything down. mnem just reads it.

Claude Code, Codex and pi each append every prompt, answer, command and edit to a transcript on disk. mnem indexes those files directly, so capture never waits on an LLM, a worker, or a queue, and one memory is shared by every agent you run.

The case

Why mnem, and where it is behind

Where mnem leads

Capture cannot silently failEvery other tool depends on a hook or an API call succeeding at the moment work happens. mnem reads the transcript the agent already wrote and commits the read position with the events, so a missed hook or crash only delays capture. mnem doctor reports lag and lost bytes instead of staying quiet.
Memories come with evidenceA summary cites the transcript events it came from, and mnem drops any citation the model was not shown. get_observations prints the evidence and flags events that changed after the memory was written. No tool we checked keeps the source behind a summary.
Problems reach you, not just the agentStuck capture, a stale backup, every model on cooldown or a stopped watcher are shown to you at session start by Claude Code and Codex. The failure that started this project, memory quietly not being saved, now has an alarm, and so does distillation falling behind: sessions about to age out undistilled raise a warning, and mnem doctor shows the backlog. An installed agent that is not connected, or whose Codex hooks are not trusted, is flagged too, with a Connect button in the viewer.
File memories know if their code survivedWhen an agent first opens a file, mnem shows past memories about it and whether the lines each one’s session wrote are still there, partly, or gone, read back from the transcript that recorded the edit. Of 354 recent memory-file pairs that could be told, 268 still had their lines, where a whole-file check called nearly all of them changed.
One memory, live across agentsClaude Code, Codex and pi read and write the same store. On every prompt, a session is told what other sessions in the same project did since it last looked. agentmemory also shares one store across agents; no tool we checked documents per-prompt “meanwhile” updates.
Recall is measured on your own promptsmnem replays real prompts from your transcripts as they were typed, hides memories created later and the asking session’s own, and has two models from different families judge what recall shows. Tuning uses one half; the other half is read once. A second set holds prompts from the weeks mnem distilled itself, and the release gate refuses a change that makes either worse. No tool we checked publishes recall measured on its user’s own work.
Nothing to babysitOne 46 MB binary with the embedding model runtime inside, and one background service. No Node, Bun, Python, Docker, vector database or cloud account. The closest light alternative, claude-mem-lite, supports Claude Code only.
Your models, no extra subscriptionSummaries go through any OpenAI-compatible endpoint (here CLIProxyAPI) with an ordered model chain. A model that hits quota cools down and the next one takes over; tested live when gemini-3.5-flash-lite returned HTTP 503.
Moving from claude-mem loses nothingImport kept all 58,797 observations with their original ids and all 4,536 summaries, then backfill recovered sessions claude-mem never captured.

Where mnem is behind

Vague questions still missA hand-written set of vague questions finds its memory in the top 5 only 60% of the time, and 3 of 10 prompts with no answer still recall something. The embedding model only reorders keyword candidates; it cannot find what shares no words with the question.
Agents rarely open what they are shownSince scripted sessions were left out, agents opened the full text of 9% of session-start memories, 4% of prompt recall and 1% of file memories, and cited 3 in 939, while judges rated about 70% of shown memories helpful. Showing fewer memories was tested and lost helpful ones (below), so noise is not the explanation; whether agents use the one-line titles without opening them is not yet known.
Vector search is brute forceEvery meaning query scans all of a project’s vectors. Fine at 64,000 memories; an index will be needed well before a million.
No knowledge graph or fact validityGraphiti and Hindsight track entities and when a fact stopped being true. mnem stores observations with timestamps only.
Three agents, not nineagentmemory supports 9 agents and claude-mem 8+ hosts. mnem covers Claude Code, Codex and pi, the three used here.
Single machine, single userNo sync, no team sharing, no cloud option.
Brand new and unproven outside this machinePrivate repository, no licence chosen, one user, no public benchmark. Mem0 publishes a LongMemEval score of 94.4 for its managed platform.
Roadmap · reviewed by a three-model council

What shipped on 28 September

The seven essentials, ordered by value to a daily user divided by effort. Each passed two code-review rounds by GPT-6 Astra, Gemini Pro Agent and Claude Fable 5.1, which found and forced fixes for real bugs before release. 60 tests cover them.

Backups with a tested restore

Shipped · 2d30707

The watch service takes a verified snapshot every night and keeps seven. Each snapshot is reopened and checked (integrity, schema, row counts, SHA-256) before it counts. mnem restore proves a snapshot on a scratch copy; --apply copies it into the live database through SQLite’s online-backup API.Council found a restore that could drop a concurrent write and one that could wait forever; both fixed and tested. Restore now gives up after 30 s with nothing changed.

Evidence links

Shipped · d8ed802

Summaries cite the transcript events behind each claim; citations outside what the model was shown are dropped. 94 links so far across 47 new memories. Imported claude-mem memories say plainly that no source was kept.Council found a citation that could slip in when a long turn was cut; the allowed list now comes from the text actually sent.

Working-tree snapshot

Shipped · 08eb2b1

At the end of each turn mnem records branch, HEAD, unpushed commits and uncommitted files. The next session in any agent opens with a “Working tree” section, labelled with its age.Runs detached with one 3 s budget for all git calls, so a slow repository never delays the agent.

Prompt recall

Shipped · 5fa3354

Each prompt adds up to five memories that match it, never repeated in a session. A memory needs two of the prompt’s words and the prompt at least one rare word; personal-detail memories are never injected automatically. (An earlier version of this page said the rare word had to be in the title; that check never existed, and adding it did not help.)Measured with the recall test: hit@5 87%, hit@1 55%, MRR 0.68, p95 about 110 ms.

Forget, exclude, remember

Shipped · e52b114

mnem forget removes memories, events, sessions or projects and leaves a marker that ingest, import and summarisation all respect. mnem remember pins facts every agent sees; mnem pins lists them.Council found three ways forgotten data could return (re-import, in-flight summaries, prompts); all closed and tested.

Health alerts

Shipped · 0fdf82a

One set of checks feeds mnem doctor, the viewer and session start, where Claude Code and Codex show alerts to the user.Expensive checks moved into the watch service; session start stays around 30 ms with no false alarms.

Export and recall evaluation

Shipped · bf0248e

mnem export writes everything as JSONL with a meta header. mnem eval builds known-item questions from real memories and reports hit rates and latency; the set stays private on the machine.Used immediately: it picked the ranking weights and rejected a change that looked good but was not.

Then, the same day: recall you can trust

Six more steps, each reviewed by the council (GPT-6 Astra, GPT-6 Sol on operations, Claude Fable 5.1) across rounds 12 to 25. Every number here comes from a test set, and the last two steps were chosen on data the tuning never saw.

Local semantic recall

Shipped · fd60843

Memories get vectors from a local model the watch service keeps loaded; hooks ask it over localhost and fall back to keywords within 300 ms. Vectors are tied to the exact text and model files they came from, so an edited memory or a new model never meets a stale vector.Council rounds 12–15 closed a stale-vector race, a revision mix-up and a port the hooks could not find.

Hybrid search for agents and the viewer

Shipped · 0244683

MCP search used to need every word, so a plain question found nothing (0% on the test questions). It now takes all-word matches, then any-word matches, fused with the nearest memories by meaning; the viewer shows one ranked list with a words / meaning badge on each card.Through MCP search: top 5 went from 0% to 85% of test questions. Pages are stable and one limit spans memories and transcript events.

Meaning gate on recall

Shipped · ddc2b94

Keyword hits that share words but not meaning are dropped before they reach the agent. Search applies a softer version to any-word matches only.Prompts with no answer that still recalled something: 9 of 10 down to 1.

Recall judged on real prompts

Shipped · b00e140

mnem eval --build-real samples real prompts, split by session into a tuning half and a test half. Each is replayed as of when it was typed; --judge has the distillation models mark what recall showed, with a second judge and its agreement on request.First labels from file overlap were dropped after reading results: they missed most relevant memories. Judges agree on 425 of 541 memories (kappa 0.57).

No more echo of the live conversation

Shipped · 6a31a01

Recall leaves out memories distilled from the session that is asking; the agent already has that conversation in context.Found by the judged eval: 43% of judged memories were the session’s own, and they took 55% of the “helpful” marks.

A better embedding model, picked on data

Shipped · d43c1a1

Seven local models screened on the tuning half; all-MiniLM-L6-v2 separated helpful from unhelpful candidates best (AUC 0.731 against 0.657; bge-small at 0.711 is within noise). Each model gets its own thresholds.Held-out, run once: helpful memories shown 149 → 179 (luna) and 100 → 141 (haiku), unhelpful 95 → 93 and 144 → 131. Trade: one test set lost two first places.

Also shipped, and one tried and dropped

Backup and move from the viewer

Shipped · 424531a

Take a verified backup in the viewer, download it, and on a new machine upload it, see it next to what that machine holds, then replace. The backup carries the settings (never keys); they are off unless ticked, and any change to where prompts go is flagged.Council rounds 26–29 found a trigger a crafted backup could smuggle in, a write that could be lost mid-restore and a missing upload deadline; all fixed and tested, including a full two-machine move.

A release gate for recall

Shipped · 2b9a905

mnem eval --gate runs the installed mnem and the candidate build (or candidate settings) on their own copies of one snapshot, graded by the same judge, and refuses the change if recall got worse: 17 checks across known, vague and judged real prompts, MCP search, personal details listed unasked, and hook latency timed in real processes.Checked: an identical build passes 17 of 17; switching the relevance gate off fails 5; a build without ONNX fails 4; a slow settings file fails on latency (631 ms). Council rounds 31–33.

Memories about a file, and whether it changed since

Shipped · 2e3f6fc

When Claude Code first reads or edits a file in a session, mnem adds up to three past memories about that file, each with how the file changed since in git (commits, uncommitted edits, lines added and removed). Any agent can ask with recall_file(path); get_observations flags memories whose files changed. About 40–170 ms, once per file.Measured first on 172 real edits: 44% had memories about the file; 74–79% judged helpful with the file named, 51% with it hidden, so about as useful as prompt recall and almost never the same memories (4 of 198). Council rounds 34–37 fixed cross-package and node_modules matches, pattern-like file names, stalled git and binary files.

Reranking the top ten: tried, not adopted

Measured · 28 Sep

Three cross-encoders scored each prompt’s ten keyword candidates on the judged real-prompt set. None beat the MiniLM gate by more than noise (AUC 0.702–0.745 against 0.713) and each took 0.9–3.4 s per prompt against a 300 ms budget.Only reordering the keyword top ten was tested; a wider candidate pool and reranking MCP search, where seconds are acceptable, remain open. mnem eval --rerank re-runs the comparison.

29 September: nothing falls behind unnoticed

Six changes, reviewed by the council (GPT-6 Astra, GPT-6 Sol, Claude Fable 5.1) in rounds 41 to 44, and one idea measured and dropped.

No session ages out of distillation unnoticed

Shipped · 36da68b

The watcher distilled only the 5 newest sessions of the last 2 days; the rest never became memories (862 in 30 days) while doctor said OK. It now distils on its own thread, then backfills the last 7 days oldest first under a daily request budget, and warns when sessions will age out. mnem distill --since-days 30 --max-calls 200 catches up older ones by hand.Council rounds 41–42. First catch-up batch: 200 calls, 539 memories, no errors.

The gate sees the memories mnem writes

Shipped · f0a6123

claude-mem stopped importing, so every new memory is distilled by mnem, yet only 4 of the 70 judged real prompts could see one. mnem eval --build-recent samples prompts from the last 30 days in projects that already held mnem memories (at most 6 per session, half per project); the gate now judges them too, with the same limits. On its first run mnem memories reached the top five for 16 of 57 prompts, and 34 of the 38 shown were judged helpful against 74 of 121 imported ones.57 prompts per half from 30 sessions; a baseline built before the set skips its checks.

Whether a memory's own edits are still there

Shipped · cbb54d1

A memory about a file said whether the file changed since, which in an active repository is nearly always: “3 of 3 predate changes” on every touch. It now says whether the lines its session left are still there, partly (how many) or gone, reading each edit back from the transcript record it came from. Of 354 recent memory-file pairs that could be told, 268 still had their lines, 77 partly, 9 not. Only memories whose edits changed count toward the warning.Council round 43: exact tool call and record identity, edits applied in order within a chunk, whole-line matches, bounded reads. File hook p95 78 ms against 75 before.

Sessions another agent scripted stay out of memory

Shipped · 5055887

24 of 2,482 sessions were driven by another agent’s brief (a review council, test runs) yet made 17% of a week’s distilled memories, and 9% of the memories shown to real sessions came from them. Prompts matching scripted_sessions patterns now mark a session: it is not distilled or offered memories, and its memories stay out of recall and the session-start context. Explicit search still finds them, labelled. Nothing is deleted.Council round 44: the last-summary line, timeline neighbours, an atomic rescan when patterns change, and search kept as a pull.

A killed gate run cleans up after itself

Shipped · 2122629

Each gate run copies the database and removes the copy when it ends. A run that was killed left a 423 MB copy behind; the next run now removes copies older than six hours.

Titles that name the thing: tried, not adopted

Measured · 1f062ec

A title rule that puts the component, file or decision first was compared on 30 chunks the live prompt had distilled, with a question per chunk written from its digest by another model. Rewriting only the titles, contents unchanged: top 5 fell from 22 to 18 of 30 and titles-only choices to open from 19 to 16. It helped where the old title named nothing (“C4.4 planning completed”) and hurt where a path or id replaced the words people ask in (“Merge train conflicts on shared test-count file” became scripts/state/test-strength.json: …).mnem eval --titles 30, then --retitle for titles alone. Re-distilling the chunks instead changed contents too and could not separate the two.

29–30 September: safer data, a lighter viewer, setup in any order

Seven changes, each reviewed before it shipped, and two viewer redesigns tried and put back.

More secrets redacted, also in what was already stored

Shipped · 352781b

A scan of everything stored found no leaks of the formats mnem already redacted, but 58 passwords in URLs (postgres://user:pass@host) in 45 imported memories and 13 events. Redaction now covers passwords in URLs and Stripe, Google, Hugging Face, npm, Slack-webhook and Telegram tokens. When the rules grow, the watcher re-redacts stored text once, in resumable batches.On this machine: 15 events and 61 memories rewritten in 12 s; a rescan finds none left. Transcripts on disk and older backups are left as they are.

A viewer light enough for low-end devices, with nothing lost

Shipped · 6525e48

Two time indexes, gzip and ETags, no web font, and a stylesheet cut to the rules the viewer can reach. Live updates pause in a hidden tab and catch up, oldest first, when it is shown.First load 583 KB → 50 KB, a reload 137 KB → 2 KB, a feed page on the server 370 ms → 3 ms, layout while scrolling at 4× slower CPU 710 → 233 ms. 27 feature checks pass on both builds: the rule was no capability lost.

Agents connect in any install order

Shipped · 1f7a7ab

mnem install writes each agent’s part whether the agent is installed yet or not. mnem install, mnem doctor and the viewer say which installed agents are not getting memory (missing hooks, tools pointing at a missing binary, Codex hooks not yet trusted); the viewer’s Connect button fixes it or shows the steps to trust Codex’s hooks.Re-running install leaves a working setup untouched; Codex’s config.toml is edited structurally and an invalid one is refused. Three Codex review rounds; six end-to-end tests in a scratch home.

Backups: daily switch and delete one

Shipped · 83cdb92, 3a3d00d

“Back up automatically every day” can be turned off in the viewer or with mnem backup --auto off; the watcher follows it without a restart, and doctor stops alerting on an old backup while it is off. Each backup can be deleted on its own, after a confirmation.Both actions sit behind the viewer’s origin and X-Mnem guard; delete accepts only a backup’s own name, never a path.

Restore strips a backup’s own schema first

Shipped · 3966782

A crafted backup’s triggers, views and indexes are dropped over a plain connection before mnem opens it, so none can run on mnem’s migration writes. The filter now skips only real sqlite_* objects (a LIKE pattern had spared a trigger named sqliteevil).Found by review while building the timeline preview. The regression test plants such triggers and fails with the old order.

A flaky distill lock

Fixed · 278f845

A lock released a moment ago could look held, because a subprocess forked by another thread keeps the lock file open until exec. Acquire now retries for 200 ms before reporting another distill.4 failures in 12 full test runs before, none in 15 after.

Two viewer redesigns: tried, put back

Put back

A three-pane viewer (filters, list, the memory in full with whether its code survived and how often agents opened it) and a live timeline at /next were both built, reviewed and run, then reverted at the user’s call: the original feed stays. The three-pane viewer is kept on branch viewer-redesign; the timeline was deleted at the user’s call, its security fix already on main.The lightweight pass above replaced them: same feed, much less weight.

1–2 October: the backlog closed, less recall measured worse, a presentation trial

One catch-up, two recall changes judged on real prompts before any code shipped, a missing alert, and a live trial of how memories are shown.

Every older session that matters is distilled

Done · 1–2 Oct

Sessions from 7 to 30 days ago that predated backfill were caught up by hand, project by project: 478 undistilled became 0 apart from five small or idle projects the user chose to leave as they are (103 sessions; their transcripts and events stay searchable). A first bounded run (up to 200 calls) took it to 336; then 215 sessions, project by project, took 200 calls and wrote 677 memories (478 observations, 199 summaries), all embedded. mnem doctor now reports fully caught up.A per-session dry run first: 63 of the 215 had nothing left to distill and cost nothing. Most of what remained were worker sessions with no prompt from the user, distilled at the user’s choice. A fresh install never builds this gap: the watcher backfills the 7 days before it first ran, then keeps up.

Fewer memories late in a session: tried, not adopted

Measured · 2 Oct

The idea: after prompt 10, show 3 memories instead of 5, require a closer meaning match, and drop or demote memories older than 7 days, since agents opened fewer of them. On the judged real prompts (70 older, 57 from the weeks mnem distilled itself), late-session memories were judged more helpful than early ones (78–90% against 37–73%), and none of 36 variants removed more unhelpful memories than helpful ones; the best dropped 18 helpful for 2 unhelpful.Simulated on each prompt’s judged top five from mnem eval --judge --dump, before writing code. A sample of 18 sessions had suggested the opposite.

Older file memories only when their edits survive: tried, not adopted

Measured · 2 Oct

Built as a setting: when an agent opens a file, skip memories older than 7 days unless their own edited lines are still there. On the judged file edits it showed 61 helpful and 18 unhelpful memories against 68 and 22 without it, and helped 28 edits against 30: seven helpful memories lost to drop four unhelpful ones. Reverted.The same build run twice on the same edits, once with each setting, judged by the same models.

Say when no memories are being made

Shipped · e83c73b

Without a distillation key, mnem captures and searches everything but writes no memories, and nothing said so. Now that is an alert in mnem doctor, the viewer and session start, and the last line of mnem install.Tested end to end in a scratch home: said with no settings, silent with a key, and the test fails with the alert removed.

Fewer memories per prompt: on trial

Running · eea360d

Agents use what they open, but memories shown and not opened leave no more trace in what the agent does next than memories never shown (9.0% against 9.1% at the same match strength, 528 shown over 139 prompts). Recall picks well; the presentation does not land. Since 2 October half of sessions, split by a hash of the session id, are shown at most 2 memories per prompt and the rest 5, in the same days.Measured after 3 to 5 days with the same check per half, and the share opened. One setting, recall.trial_top; release gate 25 of 25 with it on.

Verdict

Memory you can git blame

mnem is the best fit for this setup: three agents on one machine, models through CLIProxyAPI, and no tolerance for silently lost sessions. Search is hybrid and measured on real prompts, including the weeks mnem distilled itself, but Mem0, Hindsight and Graphiti still model entities and time, and agentmemory covers more agents.

The position is now built rather than planned. Capture that cannot lose data, distillation that cannot fall behind unnoticed, memories that cite the transcript events behind them and say whether the code they changed is still there, live updates across agents, and alerts that reach you. Every competitor summarises first and keeps no source; they cannot offer evidence or check an edit without storing full transcripts.

Next: read the presentation trial. Agents do not use the memories they are shown unless they open them, so how memories are shown now matters more than which ones.
